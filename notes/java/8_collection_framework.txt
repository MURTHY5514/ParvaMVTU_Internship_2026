Collection Framework:
=====================
* we can't able to use primitive data types in the collection.
why we need collection framework:
=================================
* to overcome the draw backs of an array.

draw backs of an array:
=======================
* it will store same type of value.
* fixed in size.
* it will take a sapce in continous memory location

advantages of an array:
=======================
* random access - arr[30]
* type safety:
==============
 the elements in side the array is based on the data type.
	int[20] --> we can store only intger values.
* type casting:
===============
  to print the values in the array  no need to type cast


Collection:
===========
* When you represent a group of individual objects as a single entity then we should go for collection.
* it is a root interface in collection framework
* we can store many data types.



List:
=====
* it is child interface of collection.
* it will contains some methods this we can use in only implemented class.
* When you represent a group of individual objects as a single entity where order is preserved and index based access and duplicate is allowd then we should go for list.


ArrayList:
==========
* Array list is a improved version of dynamic array.
* the underline data str is dynamic array.
* it will allow duplicate values.
* it will allow null values.
* order of insertion is preserved.



generics:
=========
* to over come the problem of type safety and type cast in collection framework then we should go for generics.
<T>

write our own  class as genrics:
================================
class class_name<T>{
	<T> var_name;
}

Collections:
============
* The Collections class, part of the Java Collections Framework, offers a wide range of utility methods that help reduce boilerplate code. 
1. sort(List)/reverse(List): Sorts the list into ascending order or reverses its elements.
2. binarySearch(List, key): Searches for a specified object in a sorted list.
3. shuffle(List): Randomly permutes the list.
4. min(Collection) / max(Collection): Returns the minimum or maximum element in a given collection.
5.frequency(Collection, Object): Returns the count of specific objects in a collection.
6. addAll(Collection, T... elements): Adds all specified elements to a collection.
7. copy(List dest, List src) / fill(List list, T obj): Copies elements from a source to a destination or fills a list with a single element.

comparable and comparator:
==========================
1. comparable:
==============
* if you need default or natural sorting order then we should go for comparable

2. comparator:
==============
* if you need custom sorting order then we should go for comparator interface

* A negative integer if o1 should come before o2.
* Zero if o1 and o2 are considered equal for sorting purposes.
* A positive integer if o1 should come after o2.

fuctional interface:
====================
* interface contains only one abstarct method.
ex: comparable


Set:
====
* When you represent a group of individual objects as a single entity, where insertion order is not preserved, duplicate will not allow then we should go for set interface.


Map:
====
* when you represent a group of individual objects asa single entity where in form of key value pair then we should go for map interface.
* key should be unique.
